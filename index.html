Checklist

Merging into main

For the developer merging, and for the coding agent doing the check. Run this at merge time. This page does not know whether main has moved since it was published. Do not merge, rebase, or push until the developer has seen the results. Do not use a dirty checkout. Use a temporary worktree.

  1. Fetch and measure. git fetch origin. If this pull request does not target main, say so, and still compare the branch to main. git rev-list --left-right --count origin/main...<head>. The left number is commits on main that this branch does not contain. Trust this count, not a number printed on an older copy of this page.
  2. Textual conflicts. git merge-tree --write-tree origin/main <head>. List the files. Note both-sides edits, modify/delete, rename/edit, rename/rename, binaries, and submodule SHA disagreements. GitHub mergeable: MERGEABLE only means git can produce a tree.
  3. Clean merge that still breaks. When the dry run is clean and main is ahead, read the combined tree. Any of these is a break even though git stayed silent:
    • A symbol, export, type, route, or config key removed or renamed on one side and still used on the other.
    • Two schema or migration edits that both apply: the same column, the same migration id, an enum value, or a constraint rewritten on both sides. Read order-sensitive files (migrations, route tables, version bumps) in the combined result.
    • A lockfile or package manifest changed on both sides. A clean lockfile merge can still not match the manifests.
    • Generated code merged without being regenerated.
    • Tests or fixtures changed on main in a way this branch's assertions no longer match.
    • The same user-facing flow changed in different files, caller on one side and callee on the other.
    • This branch repeats commits already squashed onto main.
  4. Checks on the combined tree. Required CI on the pull request ran against an older main when main is ahead. Advisory bot failures are not blockers. A required check that has not run on the combined tree is. Run npx tsc --noEmit and npx vitest run on the combined tree before merging.
  5. Show, then merge. Tell the developer how many commits main is ahead, the conflict files, any silent breaker, and whether CI is stale. Merge only after they agree. Then bring current main into the branch, re-run the checks, and merge into main.
